# AGENTS.md

**Read `CLAUDE.md` first.** It is the authoritative development guide for this repository: product vision, architecture, boundaries, decisions, and commands. This file only repeats the essentials for agents that do not load `CLAUDE.md`.

- Branch: **`main` is the primary development branch.** Work on `main` in the original `CameraAI` folder; do not create extra worktrees or development folders. `sentinel` and `network-diagnostics` are historical and fully merged. Never commit, stash, reset, or discard the owner's unrelated uncommitted changes; stage only the files you touched.
- Product: **Sentinel**, a local-first multi-camera property security brain (`src/sentinel/`). A drone is a future mobile camera behind an operator-approval gate (`src/sentinel/drone/`).
- Legacy and frozen: `src/senior_safety/` and `webapp/` (former CameraAI senior-safety project). Keep their tests passing and do not extend them.
- Tests: `PYTHONPATH=src python -m unittest discover -s tests`. All tests must pass before a commit.
- Demo: `PYTHONPATH=src python -m sentinel serve` serves simulated cameras and a dashboard at http://127.0.0.1:8080.
- Setup: cameras, zones, masks, map, connections, and categories are edited in the dashboard (Setup tab) through `/api/v1/config/*` and `/api/v1/onboarding/*`. The network troubleshooter (`src/sentinel/netdiag/`) is read-only: never change router, firewall, computer or device settings, and never probe public addresses. See `docs/camera-setup.md`.
- Detection: YOLOX via ONNX Runtime (`detector.model: auto`), EfficientDet fallback; category filters in `categories`. See `docs/environmental-intelligence.md`.
- Never: return or log stream URLs or passwords, claim intent or identity in alert text, merge uncertain cross-camera identities, expose camera streams publicly, commit secrets or media, enable physical drone flight commands, or add AGPL dependencies (for example Ultralytics YOLO).
- Intelligence: rules are edited and tested in Setup → Rules (`rules.py`, `rule_lab.py`), incidents are explained as observed vs inferred (`explain.py`), activity statistics are information only and never alert or change rules (`insights.py`), and feedback is for evaluation only (`reports.py`). See `docs/intelligence.md`.
- Reliability: a camera is reported as monitoring only while frames reach a working detector and nothing shows the picture is frozen; unprovable still pictures are `unverified` (`health.py`). Workers are supervised (`supervisor.py`), disk space is guarded (`storage_guard.py`), backups and startup recovery live in `backup.py`, and background running in `daemon.py` (`sentinel run`, `sentinel service`). Health events never open incidents. See `docs/reliability.md`.
- Installation: the Install tab (`web/install.js`) runs four paths (existing cameras, new cameras, drone-first, complete package) over `devices.py` (registry and hardware profiles), `planner.py` (property planner, approximate coverage) and `installation.py` (saved progress, readiness). A site may have no cameras. Registration is never connection: levels registered / connected / video / AI verified are earned from received data, and Sentinel never says a property is protected. See `docs/installation.md`.
- Assistant: Sentinel AI Guide (`src/sentinel/assistant/`, Guide tab). It reads live data through a fixed tool set and can only *propose* changes; a person confirms each one, and the existing backend applies it. No shell, file, router, firmware, secret or flight tools. Passwords go only through the secure sign-in form, never the conversation; addresses are replaced by placeholders before anything goes to an external AI provider (off by default). See `docs/assistant.md`.
- Plan of record: `ROADMAP.md`. Architecture: `docs/architecture.md`. API: `docs/api.md`. Drone: `docs/drone-integration.md`.
